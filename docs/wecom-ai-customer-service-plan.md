# 企业微信 AI 客服接入实施方案



| 项    | 内容                                                         |
| ---- | ---------------------------------------------------------- |
| 版本   | v0.1                                                       |
| 日期   | 2026-09-02                                                 |
| 所属项目 | AstraFlow（easy-ai-starter 框架 + easy-ai-starter-test 测试工程） |
| 场景   | 外部客户群聊（S1）+ 外部私聊（S2）                                       |
| 规模   | 10 个企微客服账号、2000 个客户群                                       |



***

## 1. 背景与目标

### 1.1 项目现状（可复用能力）

AstraFlow 框架已完成以下能力，本次接入全部复用：



* 注解驱动任务模型（`@AiTask` / `@AiTaskParam` / `@AiField` / `@AiExtract` / `@AiPremise` / `@AiMapping` 等）

* 意图识别（LLM 判断 + 置信度 + `intentReason` 记录）

* 多轮参数收集、字段 Normalization、Validator、字段映射

* `DefaultTask` 无匹配兜底

* 多 LLM Provider（deepseek /kimi/doubao /qwen）

* `(tenantId, sessionId)` 双维度租户隔离（均为 String）

* `POST /easyai/engine/chat/auto`（自动意图 + 任务流转）、`/chat/stream`（SSE 流式）

### 1.2 接入目标



| 场景        | 说明                       | 通道                  |
| --------- | ------------------------ | ------------------- |
| S1 外部客户群聊 | 客户在客户群里提问，AI 全自动回复       | 会话存档（读）+ RPA 自动化（写） |
| S2 外部私聊   | 客户通过微信客服入口一对一咨询，AI 全自动回复 | 微信客服 Kf API（读 + 写）  |

### 1.3 硬性约束



1. **全自动**：不接受人工确认 / 人工代发，回复必须由程序自动发出。

2. **实时性**：从收到消息到发出回复，端到端 **≤ 10 秒**。

3. **规模**：10 个企微客服账号、2000 个客户群，峰值并发十几条。

4. **已开通会话存档**：读侧能力已具备。

## 2. 官方能力边界（已核实）

> 结论先行：
>
> **官方 API 层没有任何 "程序直发外部客户群" 的开放通道**
>
> 。群聊全自动只能走「会话存档（读）+ 自动化工具（RPA 写）」；私聊全自动走「微信客服」。



| 通道                      | 收消息             | 发消息                           | 外部客户可用      | AI 自动可用性      | 结论          |
| ----------------------- | --------------- | ----------------------------- | ----------- | ------------- | ----------- |
| 微信客服 Kf API             | ✅ `kf/sync_msg` | ✅ `kf/send_msg`               | ✅ 微信生态客户    | ✅ 全自动         | **S2 私聊首选** |
| 智能机器人                   | ✅（@/ 单聊）        | ✅                             | ❌ 仅内部群      | ❌             | 不适用         |
| 群机器人 Webhook            | ❌ 只发不收          | ✅ 单向                          | ❌ 外部群暂不支持   | ❌             | 不适用         |
| 客户联系 / 外部联系人            | ❌ 无 AI 回调       | ⚠️ 群发需成员确认                    | ✅           | ❌             | 不适用         |
| 会话存档                    | ✅ 付费拉取          | ❌ 只读                          | ✅ 含外部群 / 私聊 | 读 ✅ / 写 ❌     | **S1 读侧**   |
| 企业群发 add_msg_template | —               | ⚠️ 必须成员确认，且同群约每天 1 条 / 每月 4 条 | ✅           | ❌             | 仅通知场景       |
| 官方「客户群自动回复」             | —               | —                             | ✅           | ⚠️ 静态关键词，非 AI | 兜底          |

**关键事实（附官方依据）：**



* 群机器人 Webhook：官方帮助中心明确「内部群聊支持消息推送，外部群暂不支持」；开发者社区 2025-11 确认「暂不支持相关功能」。

* 智能机器人：仅支持内部群，外部群 / 上下游 / 互联群不支持。

* 企业群发：`add_msg_template` 调用后**需要成员在企业微信客户端确认才会发送**，且存在频控，不适合实时对话。

* 会话存档：仅保留近 5 天数据，单次 1000 条，需拉取后解密；按存档人数购买席位。

**结论**：S1 群聊的「写」侧，官方无 API 可用，只能使用 **RPA/UI 自动化**（程序驱动企微 PC 客户端模拟真实员工发送）。这是全自动的唯一技术路径。

## 3. 总体架构



```
                         ┌────────────────────────────────────────────┐
                         │              AstraFlow 引擎（复用）           │
                         │  意图识别 / 任务编排 / 多轮收集 / DefaultTask │
                         └───────────────▲────────────────────────────┘
            ┌────────────────────────────┼────────────────────────────┐
            │                            │                            │
   ┌────────┴────────┐         ┌─────────┴─────────┐        ┌─────────┴─────────┐
   │ S1 读侧         │         │ S2 私聊           │        │ S1 写侧           │
   │ 会话存档拉取    │         │ 微信客服回调      │        │ 回复队列 → 调度器  │
   │ 解密 → 过滤     │         │ sync_msg → 回复   │        │ → RPA Worker×10   │
   └────────▲────────┘         └───────────────────┘        └─────────▲─────────┘
            │                                                          │
   外部客户群（客户提问）                                    企微 PC 客户端 ×10（模拟发送）
            ▲                                                          │
            └────────────────── AI 回复回到客户群 ◄────────────────────┘
```



* **读侧**（S1 + S2）：高并发无 UI 瓶颈，消息进来后并行喂给 AstraFlow。

* **写侧**（S1）：多 Worker 并行，每个 Worker = 1 个企微账号 + 1 个 PC 客户端 + 1 个 RPA 进程。

* **调度器**：把 AstraFlow 产出的回复按 `chat_id` 归属分发到对应 Worker 的发送队列，并做合并 / 节流 / 降级。

## 4. 场景一：外部客户群（核心场景）

### 4.1 读取链路（会话存档）



```
会话存档拉取（定时 1\~2s + 增量 seq）
  → 去重（msgid）
  → 解密（企微 RSA 公钥 + AES-CBC）
  → 相关性四级过滤
      L1 防自触发：机器人自身消息、系统消息、撤回消息
      L2 硬过滤：非文本、无实际语义（纯表情/纯@等）、明显无关主题
      L3 上下文放行：该群存在进行中的 AstraFlow 任务时放行（可能是补充参数）
      L4 LLM 置信度：意图/相关性置信度 ≥ 0.8 才进入处理（宁漏勿误）
  → 调 AstraFlow：POST /easyai/engine/chat/auto
      sessionId = chat_id
      tenantId  = corpId（企微企业 ID）
```

### 4.2 发送链路（RPA 多 Worker 并行）

**为什么必须多 Worker**：企微 PC 端同一时刻只能聚焦一个会话窗口，单客户端 "激活→粘贴→回车" 约 2\~3s / 条，吞吐仅 20\~30 条 / 分钟。峰值十几条并发、要求 10s 内回复 = 72 条 / 分钟，**单客户端物理上做不到**，必须水平扩展。

**架构**：



| 项           | 设计                                                            |
| ----------- | ------------------------------------------------------------- |
| Worker 数    | 10（= 10 个企微客服账号，企微限制单账号仅一个 PC 端在线）                            |
| 每 Worker 群数 | 2000 ÷ 10 = 200 群 / 账号（< 单账号约 500 群上限，安全）                     |
| 分片策略        | **活跃度加权分片**：按近 7 天消息量对群排序，高频群均匀散到 10 个账号，避免热点群扎堆同一账号；分片表可动态重算 |
| 索引缓存        | `chat_id → 输入框 UIA 元素` 映射表，启动构建 + 增量维护（新群 / 掉线重登后重建）          |
| 发送动作        | 命中索引 → 激活窗口 → 聚焦输入框 → 剪贴板粘贴 → 模拟回车（条件等待替代固定 sleep）            |
| 并发模型        | 每 Worker **单线程串行发送**（避免并行抢 UI 焦点）                             |

**窗口预热（关键提速）**：调度器把回复派给 Worker 后，Worker 立即先激活 / 聚焦目标群窗口（约 1.5s），此时 LLM 生成仍在进行；回复就绪时窗口已就位，粘贴 + 回车 <0.5s。整体延迟 ≈ max (LLM 生成，窗口预热) + 0.5s ≈ 8.5s，达标 10s。

### 4.3 调度器



```
全局消息队列（Redis Stream/List，按 worker 分片为 10 个队列）
分发规则：
  1\. 按分片表：chat_id → workerId（固定归属）
  2\. 批处理合并：同一群 2s 窗口内多条消息合并为一条回复（省发送次数、降频控压力）
  3\. 优先级：VIP 群（打标）优先出队
  4\. 频控节流：按账号每日/每分钟配额限制出队，超预算的降级
  5\. 降级策略：
     \- 超时未发（如 >15s）→ 记录日志 + 可选转私聊引流
     \- 超频控配额 → 排队等待下一窗口 or 放弃并告警
```

### 4.4 S1 时序（单条消息）



```
客户在群发言
  → 会话存档拉取（≤2s 轮询）→ 解密 → L1\~L4 过滤
  → 调 /chat/auto（AstraFlow 生成回复，约 5\~8s）
  → 回复入队 → 调度器按 chat_id 分发给 Worker-x
  → Worker-x：索引命中 → 激活窗口/聚焦输入框（并行于 LLM 生成）
  → 粘贴 + 回车（<0.5s）
  → 消息出现在客户群
```

## 5. 场景二：外部私聊（微信客服）

### 5.1 开通



1. 企微管理后台开通「微信客服」，创建客服账号（如 "AI 客服"）。

2. 在「微信客服 - 开发配置」配置回调 URL（填部署后的回调接口），获取 token /encodingAESKey。

### 5.2 接收（读）



* 客户从公众号 / 小程序 / 网页 / 微信内入口发起会话（无需加好友）。

* 企微推送**事件回调**（仅通知 "有新客服消息需要同步"）。

* 服务端调 `kf/sync_msg` 主动拉取明文消息。

### 5.3 回复（写）



* `kf/send_msg` 发送文本 / 图片 / 文件等，天然并发、无 UI 瓶颈，可秒回。

### 5.4 会话映射



```
sessionId = openKfid + "_" + externalUserId   // 客户维度，稳定可复用多轮
tenantId  = corpId                            // 企业维度，租户隔离
```

### 5.5 附加能力



* 欢迎语 / 提示语 / 会话结束语：`kf/send_msg_on_event`。

* 客户满意度评价、会话标签等可选。

## 6. AstraFlow 框架侧改造

### 6.1 新增模块：`wecom-adapter`（建议独立 Maven 模块或子工程，避免污染 starter 核心）



```
com.link.easyai.wecom
├── controller
│   └── WecomCallbackController        // 企微回调验签/解密/响应（echo 校验 + 事件）
├── archive
│   ├── MsgArchiveFetcher              // 会话存档拉取（增量 seq + 定时/事件触发）
│   ├── MsgArchiveDecryptor            // RSA + AES-CBC 解密
│   └── MsgArchiveProperties           // 存档密钥/套餐配置
├── filter
│   └── CorrelationFilter              // L1\~L4 四级相关性过滤
├── kf
│   ├── KfMsgClient                    // 微信客服 sync_msg / send_msg / send_msg_on_event
│   └── KfProperties
├── dispatcher
│   ├── ReplyQueue                     // 回复队列（对接 Redis）
│   ├── ShardTable                     // chat_id → workerId 分片表（活跃度加权）
│   └── ReplyDispatcher                // 分发 + 合并 + 优先级 + 频控节流
├── rpa
│   ├── RpaWorkerClient                // 发送指令接口（供 RPA 端轮询消费）
│   └── RpaWorkerProperties
├── session
│   └── ExternalSessionMapper          // 外部会话 ↔ AstraFlow sessionId/tenantId 映射
└── service
    ├── GroupChatIngestService         // S1 群消息接入编排
    └── KfChatIngestService            // S2 私聊接入编排
```

### 6.2 配置项（application.yml）



```
wecom:
  corp-id: ""                 # 企业 ID
  contact-secret: ""          # 客户联系 secret（会话存档/外部联系人）
  callback:
    token: ""
    encoding-aes-key: ""
  archive:
    public-key: ""            # 会话存档公钥（加密文件用）
    private-key: ""           # 会话存档私钥（解密用，由管理员生成）
    seed: ""                  # 会话存档随机字符串
  kf:
    secret: ""                # 微信客服 secret
  rpa:
    workers: 10               # Worker 数
```

### 6.3 与既有能力复用



* 直接调用 `POST /easyai/engine/chat/auto`（`sessionId`/`tenantId` 已在 4.1 / 5.4 定义）。

* 复用 `DefaultTask` 兜底、租户隔离、多 Provider。

* 建议为 S1/S2 各配一个独立 `tenantId` 前缀（如 `corp_<corpId>_group` / `corp_<corpId>_kf`），避免两类会话串扰。

## 7. 非功能性设计

### 7.1 实时性预算（端到端 ≤ 10s）



| 环节           | 预算         | 优化手段                        |
| ------------ | ---------- | --------------------------- |
| 拉取 + 解密 + 过滤 | \~2s       | 轮询间隔 1\~2s；过滤走内存规则 + 少量 LLM |
| LLM 生成       | \~6s       | 与窗口预热并行；必要时流式 / 换更快模型       |
| 发送           | \~0.5s     | 索引缓存 + 窗口预热，就绪即发            |
| **合计**       | **≈ 8.5s** | ✅                           |

### 7.2 频控预算（最大风险项，需实测）



* 企微反骚扰：单账号约**每分钟 ≤20 条、单日 ≤200 条**（对外消息，口径需实测确认）。

* 10 账号合计 ≈ **单日 2000 条**。若 2000 群日均咨询 >1 条 / 群会超限。

* 对策：批处理合并（同群多条合并一条）、按账号配额节流、超预算降级引流微信客服。

### 7.3 稳定性



* 每个 Worker 独立进程；企微客户端掉线 / 重登后自动重建索引并续跑。

* 心跳 + 告警：Worker 失联、队列积压、频控触发、客户端异常均告警。

* 灰度：先 1 账号、100 群试运行，稳定后扩展到 10 账号 2000 群。

### 7.4 成本估算



| 项    | 口径                               | 备注                   |
| ---- | -------------------------------- | -------------------- |
| 会话存档 | 按存档人数购买席位（约 900\~1800 元 / 人 / 年） | 10 个客服账号均需，以官方最新报价为准 |
| 服务器  | 10 Worker + AstraFlow + Redis      | 按并发与 LLM 调用量估算       |
| RPA  | 自研 Python 免费 / 第三方 RPA 平台付费      | 推荐自研                 |
| 企微认证 | 企业已认证则无额外费用                      | —                    |

## 8. 分阶段实施计划



| 阶段                   | 内容                                       | 交付物      | 验收标准                | 工期       |
| -------------------- | ---------------------------------------- | -------- | ------------------- | -------- |
| **P0 预研压测**          | 频控实测、单条发送耗时、客户端稳定性                       | 压测报告     | 确认日发送上限、单条 2\~3s 达成 | 0.5\~1 周 |
| **P1 私聊 MVP**        | 微信客服回调 + sync_msg + AstraFlow + send_msg | S2 全链路   | 微信端私聊 10s 内回复       | 1 周      |
| **P2 群读链路**          | 会话存档拉取 + 解密 + L1\~L4 过滤 + AstraFlow        | S1 读侧    | 群消息正确进入任务、过滤不误伤     | 1 周      |
| **P3 群写单 Worker**    | RPA 单账号：索引缓存 + 串行发送 + 窗口预热               | S1 单账号闭环 | 单账号 200 群，10s 内回复   | 1 周      |
| **P4 多 Worker + 调度** | 分片表 + 调度器 + 合并 / 节流 / 降级                 | 10 账号全量  | 峰值十几并发 10s 内；频控不触发  | 1 周      |
| **P5 稳定化 / 灰度**      | 自动重登、监控告警、灰度 100 群→2000 群                | 生产就绪     | 连续运行 7 天无中断、无风控     | 1 周      |

> 关键路径：P0 的频控实测决定 P4 的调度参数，建议最先启动。

## 10. 待确认项与参考资料

### 10.1 待确认项（实施前必须敲定）



1. 企微反骚扰**频控实测值**（每分钟 / 每日对外消息上限、AI 回复是否计入）。

2. 会话存档**计费口径**与 10 账号年成本。

3. 单账号客户群数量上限复核（官方后台实际配置）。

4. RPA 技术栈选型：**自研 Python（pywinauto/UI Automation） vs 第三方 RPA 平台**。

5. 微信客服主动发送的时效限制实测。

6. AstraFlow 与企微对接的部署位置（同一服务 / 独立 wecom-adapter 服务）。
